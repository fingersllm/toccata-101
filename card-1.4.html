Addresses and locks: key-locked and script-locked outputs

What protects your funds? Every Kaspa address is a lock on UTXOs, and Kaspa has two kinds of lock.

A Kaspa address is not an account, it doesn't hold funds. An address's mission is to spell out the lock an output will carry. Kaspa has two kinds of these locks:

  1. 1A key lock: starts with q, the address is a public key in disguise. kaspa:qpc6655zfnql67…kzy9jz8q is the 32 bytes of a key, dressed with a checksum so a typo is caught. The lock says: this key must sign. Whoever holds the matching private key can spend, and that is what your wallet does for you.
  2. 2A script lock: starts with p, kaspa:pzzgtjkyzsgxp24…c62fn0pl is the fingerprint of a script, 32 bytes of hash. To spend it, you have to show the script itself. The node takes the script, checks that its fingerprint matches the address, and then runs it. Only when the script is satisfied does the UTXO move. Every covenant since Toccata is a script, so all of them live behind p addresses.

From a p address alone you cannot read the script, only its fingerprint, until someone spends it or publishes it. Your wallet shows both kinds as UTXOs. The lock decides what the spend must show.

Look at it on chain

Two transactions from 6 September 2026, the same pair card 1.3 weighed.

  1. One transaction, both locks. 60a2f205…3f145914 created a p output, 0.3 KAS to kaspa:pzzgtjkyzsgxp24…c62fn0pl, and a q output, the change to kaspa:qpc6655zfnql67…kzy9jz8q.
  2. The script comes out. 2436d2fc…f7501f3d spent the p output. Its signature script holds a 65-byte signature and then the script itself, 187 bytes. Hash the script and you get the 32 bytes inside the p address.
20 71ad52824cc1fd78…dabfd9b3 ac push a public key, OP_CHECKSIG
00 63 07 6b6173706c6578 00 4c 8b 7b2270223a226b72632d3230… 68 OP_FALSE OP_IF, a note the node never runs, OP_ENDIF

The script says: this key must sign, and it carries a note for an off-chain indexer (a KRC-20 transfer) that the node skips. The key in that script, 71ad…d9b3, is the key inside the q address. Same key, two locks.

Sources

An address is a prefix, a version byte and a payload, with an 8-character checksum, in rusty-kaspa v2.0.1 crypto/addresses/src/lib.rs (versions 0 PubKey, 32 bytes, 1 PubKeyECDSA, 33 bytes, 8 ScriptHash, 32 bytes) and bech32.rs (the charset and the checksum). The lock each address stands for is built in crypto/txscript/src/standard.rs: OpData32 <key> OpCheckSig, OpData33 <key> OpCheckSigECDSA, OpBlake2b OpData32 <hash> OpEqual, the hash being blake2b-256 of the script. Opcode values are in opcodes/mod.rs. The decoder on this page is a line-by-line port of bech32.rs, checked against the node's own test vectors. The two transactions were read from api.kaspa.org on 6 September 2026. The revealed script was hashed with blake2b-256 and matched to the p address.
