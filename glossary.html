Glossary

The terms the cards use, one short explanation each. Tap a term on any card and it opens here. New terms join as the cards land.

68 terms
ABCDEFGHIJKLMNOPQRSTUVWXYZ

A
address
The lock an output will carry, spelled out in letters. A q address carries a public key, a p address the fingerprint of a script.
B
block
A batch of transactions sealed by proof of work, pointing at earlier blocks. Kaspa makes ten a second.
blockDAG
Kaspa's ledger: blocks made in parallel, each pointing at several earlier blocks, so together they form a DAG.
block timestamp
The time a miner's node writes into a block, in milliseconds since 1970. Nodes refuse one too far ahead of their clock or not after the past median time.
blue block
A merged block with at most 124 blue blocks beside it that never saw it. It counts in the blue score, and its miner is paid.
blue score
The number of blue blocks in a block's past. The newest block's blue score minus an older one's is how many blocks sit on top of it.
blue work
The proof of work behind a block, counting blue blocks only. The rule that picks the chain compares it.
byte
Eight bits, the unit data is counted in. One letter of plain text is one byte, a key is 32.
C
chain block
A block on the network's main line. It merges the blocks beside it, accepts their transactions and pays their miners.
change
The output a wallet sends back to your own address: what is left of the inputs after the payment and the fee.
checksum
The last eight characters of an address, worked out from the rest, so a typo is caught before any coin moves.
coin age
How far the DAA score has climbed since the block that accepted a coin. Every coin carries its own starting score.
confirmation
A block added on top of the one that accepted your transaction. The reference wallet calls a payment confirmed after 100, about ten seconds.
covenant
A UTXO whose script sets rules on the transaction that spends it, such as where the coins go and what the next output holds.
Crescendo
The Kaspa hardfork that took the network from one block a second to ten and let a script read its transaction's amounts and addresses.
D
DAA score
The network's count of blocks, about ten every second.
DAG
Directed acyclic graph: items that each point back at earlier ones, where following the pointers never leads back to the start.
difficulty
How hard it is to find a block: the easiest target divided by the current one. It adjusts so the network keeps making ten blocks a second.
E
explorer
A website that shows what is on chain: blocks, transactions, addresses and their UTXOs.
F
fee
A transaction's inputs minus its outputs, paid to a miner.
fee rate
A transaction's fee divided by its mass, in sompi per gram. Miners take the highest fee rates first.
fingerprint
The hash of a script, 32 bytes, the part a p address carries. The script cannot be worked out from it.
G
gram
The unit a transaction's mass is counted in. A fee is a price per gram.
H
hardfork
A change to Kaspa's rules that starts at a set DAA score. Every node must update, or it splits off from the network.
hash
A fixed-size value worked out from any data, 32 bytes on Kaspa. Change one byte of the data and the hash changes completely.
I
input
The part of a transaction that points to the UTXO it spends and carries what unlocks it, usually a signature.
introspection
A script reading the transaction that spends its UTXO, such as its inputs and outputs, their amounts and their addresses.
K
KAS
Kaspa's coin. 1 KAS is 100,000,000 sompi.
key lock
The lock a q address stands for: this key must sign. Whoever holds the matching private key can spend.
KRC-20
A token convention that writes a note into a transaction's script for software outside the node to read. The node itself skips the note.
L
Layer 1 (L1)
The Kaspa network itself, where every node checks every transaction.
lock
The script on an output that decides what a spending transaction must show. Its technical name is the script public key.
M
mainnet
The real Kaspa network, where KAS has value. Its addresses start with kaspa:, a test network's with kaspatest:.
mass
A transaction's weight in grams. It has a size weight and a storage weight, and the heavier one sets what a wallet pays.
mempool
The transactions a node has checked and holds until a miner puts them in a block.
merge set
The blocks a block brings into the order: everything in its past that its selected parent had not covered.
miner
Someone who builds blocks and does the proof of work that seals them, collecting the subsidy and the fees.
N
node
A computer running Kaspa's software that checks every transaction and block against the rules and keeps the UTXO set.
O
output
An amount of KAS and a lock, created by a transaction.
P
p address
An address that starts with p. It carries the fingerprint of a script, and a spend must show the script and meet it.
parent
An earlier block a new block points at. A Kaspa block points at up to 16 of the newest blocks its miner saw.
past median time
The middle of the times written on recent blocks, worked out by every node. A new block's time must be later, so network time never runs backwards.
peer
Another node this node is connected to. Nodes pass transactions and blocks to their peers, and every peer checks them for itself.
piece
Another word for a UTXO.
private key
The secret a wallet makes from its seed and keeps. Whoever holds it can spend what its public key locks.
proof of work (PoW)
The work a miner does to make a block valid: trying number after number until the block's hash is at or under the target.
public key
The key an address is made from, safe to show. A signature made with the matching private key checks against it.
Q
q address
An address that starts with q. It carries a public key, and a spend must show that key's signature.
R
red block
A merged block with more than 124 blue blocks beside it that never saw it. It is kept and its transactions count, but its miner is not paid for it.
S
script
A small program of one-byte instructions that every output carries. Every node runs it when the output is spent.
script lock
The lock a p address stands for: show the script that matches the fingerprint, then meet it. Every covenant lives behind one.
script public key
The technical name of an output's lock: the script that sets the conditions for spending the output.
selected parent
Of a block's parents, the one with the most blue work behind it. Following selected parents back from the newest block gives the chain.
signature
A proof made from a hash of the transaction with a private key. Every node checks it against the matching public key.
signature script
The script an input carries to unlock the output it spends. It may only put data on the stack.
size weight
The weight of a transaction's bytes and of checking it, about 2,000 grams for a plain payment, whatever the amounts.
sompi
The smallest unit of KAS, and the one every amount on Kaspa is counted in. 1 KAS is 100,000,000 sompi.
spend
To use a UTXO as a transaction's input. Once the transaction is accepted, every node removes that UTXO from its UTXO set.
stack
The single-ended list a script works on: instructions take data from the top and put their results back on top. It holds at most 244 items.
storage weight
The weight of the new pieces a transaction creates: about 10¹² divided by each piece's value in sompi, less a relief for the pieces it spends. Small pieces are heavy.
subsidy
The new KAS a block brings into existence. The rules set it by the block's DAA score, and it shrinks every month.
T
target
The number a block's hash must be at or under. The lower the target, the more tries it takes to find a block.
Toccata
The Kaspa hardfork that brought covenants: a UTXO's script can read the whole transaction, keep state between spends and carry an identity.
transaction
A transfer that spends UTXOs as its inputs and creates new outputs. Every node accepts it whole or refuses it whole.
U
Unix time
How computers count a moment: the seconds, or milliseconds, since the start of 1 January 1970 UTC.
UTXO
Unspent transaction output: an output no transaction has spent yet. A wallet's balance is the sum of its UTXOs.
UTXO set
Every unspent output, kept by each node. A transaction's inputs must be in it, and each accepted transaction takes its inputs out and puts its outputs in.
W
wallet
The software that keeps your keys, adds up the UTXOs they can unlock, and builds and signs your transactions.
